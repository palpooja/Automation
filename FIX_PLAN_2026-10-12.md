## The six suggestions received with that log

1. **Direct requests everywhere** (Level 2, return PDFs, certificates with `context.request`).  Level 3 already works
   this way (10.16) and is proved once per client (10.17).  Level 2 export costs no request at all: the portal's
   Export To Excel is script that copies the on-screen table.  The Level 2 page, the return pages and the
   certificate search could be fetched directly, but their request shapes (form fields, tokens, how the portal
   renders a return for print) are not captured.  To do it safely: run one Returns type and one WHT month with
   `URA_DEBUG=1` from Uganda and send the log; the requests in it are the specification.
2. **Block images, CSS and fonts from ura.go.ug after login.**  Not done on purpose: the WHT date selector's arrows
   are images and the calendar is laid out by CSS and read by screen position; the program's "is it visible"
   checks and the live-portal rule "a mouse click can land on whatever lies on top" depend on the layout.  The
   portal's pages are small tables; the time goes in round trips, not bytes.
3. **Two or three requests at a time.**  Possible for the direct Level 3 way (one JavaScript fetch per month);
   from Uganda a month takes about 1 s, so the gain is small there and the risk (the portal's lastEventTS and
   session rules under parallel requests) is unknown.  Worth doing only after item 1's captures.
4. **Skip return types and tax heads the client does not have.**  The portal offers the same 17 return types and
   lists every tax head for every taxpayer; the registration details page is not captured.  Until it is, untick
   the types on the Returns page; from Uganda an empty check costs about 2 s.
5. **First Back press and the empty Local Excise Duty ledger.**  Done in 10.17 (the Back had worked; Level 2 was
   slow - the program now watches the browser's requests; the empty ledger is taken by its headings).
6. **PAYE search never fires.**  Done in 10.17.  The cause found in the code was not the period's onchange (the
   period is set with select_option, which fires change): a bare "Search" selector was tried in every frame and
   pressed the public site's search box on the outer page.  One retry at most; a press that never sends is given
   up after 16 s and never repeated at the end of the client.
